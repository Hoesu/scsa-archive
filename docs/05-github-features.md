# 05. GitHub 기능 둘러보기

이 저장소는 GitHub 의 협업 기능을 **골고루 써볼 수 있도록** 설계되어 있습니다.
각 기능이 여기서 어떻게 쓰이는지 보고, 아래의 **실습 미션**으로 직접 경험해 보세요.

## 기능별 사용처

| 기능 | 이 저장소에서의 용도 | 실무에서는 |
|---|---|---|
| **Issues** | 문제 제안, 질문, 개선 요청 | 버그 리포트, 기능 요청, 할 일 관리 |
| **Issue Forms** (템플릿) | 제안/질문 시 필요한 항목을 빠짐없이 받기 | 버그 재현 정보 수집 |
| **Labels** | 유형(`문제-제안`, `풀이`), 상태(`채택`), 플랫폼, 난이도 분류 | 우선순위, 담당 팀, 상태 분류 |
| **Assignees** | 문제 등록을 누가 맡았는지 표시 | 담당자 지정 |
| **Branch** | 풀이/문제 하나마다 브랜치 하나 | 기능 하나마다 브랜치 하나 (feature branch) |
| **Pull Request** | 풀이·문제 등록을 `main` 에 합치기 전 검토 | 모든 코드 변경의 관문 |
| **Draft PR** | 아직 풀이 중인 코드 공유, 중간 피드백 | 작업 중인 코드 미리 공유 |
| **Code Review** | 줄 단위 코멘트, Approve / Request changes | 품질 관리, 지식 공유 |
| **Suggested changes** | 오타·변수명 수정 제안 → 버튼 한 번에 반영 | 동일 |
| **Closing keywords** | PR 본문의 `Closes #12` 로 제안 이슈 자동 종료 | 이슈-코드 연결 추적 |
| **Branch protection** | `main` 직접 푸시 금지, 승인 1개 필수 | 동일 |
| **GitHub Actions** | PR 규칙 자동 검사, 라벨 자동 부착, 목록 자동 생성 | CI/CD |
| **Milestones** | 주차별 "이번 주 문제 세트" | 릴리스/스프린트 단위 관리 |
| **Projects** | 칸반 보드: 제안됨 → 이번 주 → 완료 | 팀 작업 현황판 |
| **Discussions** | 공지, 주간 회고, 자유 토론, 알고리즘 Q&A | 커뮤니티 포럼 |
| **Mentions** `@id` | 특정 사람에게 리뷰·답변 요청 | 동일 |
| **Reactions** 👍 | 문제 제안 투표 | 의견 수렴 |
| **Contribution graph** | 내 커밋·PR·리뷰가 프로필 잔디에 기록 | 포트폴리오 |

## 이런 상황엔 어디에?

```
질문/이야기가 있다
├── 특정 풀이 코드의 특정 줄에 대한 것?        → 그 PR 의 Files changed 에서 줄 코멘트
├── 특정 문제에 대해 막혔다/궁금하다?           → Issue (풀이 질문 템플릿)
├── 저장소 규칙/스크립트가 이상하다?            → Issue (저장소 개선 템플릿)
└── 그 외 (공지, 회고, 알고리즘 일반 질문, 잡담) → Discussions
```

## 주간 운영 방식 (Milestone + Projects)

1. 운영진이 매주 월요일 Milestone 을 만듭니다. 예) `Week 03 (11/16 ~ 11/22)`
2. `채택` 된 제안 이슈 중 3~5개를 이번 주 Milestone 에 넣습니다.
3. **Projects 보드**에서 진행 상황을 봅니다.

| 제안됨 | 이번 주 문제 | 등록 완료 | 이번 주 종료 |
|---|---|---|---|
| 새 제안 이슈 | Milestone 에 포함된 이슈 | 문제 PR 머지됨 | 회고 완료 |

4. 금요일에는 **Discussions 의 주간 회고** 스레드에 "이번 주 가장 배운 점"을 한 줄씩 남깁니다.
5. Milestone 페이지에서 진행률(%)을 확인할 수 있어요.

## 실습 미션 🎯

체크하면서 하나씩 해보세요. 전부 하면 실무 협업 흐름을 한 바퀴 돈 것입니다.

**Level 1 — 첫 기여**
- [ ] 저장소에 ⭐ Star 누르기, **Watch → Custom → Pull requests, Issues** 설정하기
- [ ] Discussions 의 자기소개 스레드에 인사 남기기
- [ ] 예시 문제 `programmers/12906` 에 내 풀이로 첫 PR 올리기
- [ ] 자동으로 붙은 라벨과 `validate` 검사 결과 확인하기

**Level 2 — 리뷰 주고받기**
- [ ] 다른 사람 PR 에 `[질문]` 또는 `[제안]` 코멘트 1개 남기기
- [ ] **Suggested change** 로 제안해 보기 / 받은 제안을 **Commit suggestion** 으로 반영해 보기
- [ ] 다른 사람 PR 을 **Approve** 하기
- [ ] 내 PR 을 **Squash and merge** 하고 브랜치 삭제하기

**Level 3 — 문제 은행 키우기**
- [ ] 문제 제안 Issue 올리기
- [ ] 다른 사람의 제안에 👍 리액션으로 투표하기
- [ ] 채택된 이슈를 Assign 받아 문제 등록 PR 올리기 (`Closes #번호` 로 이슈 자동 종료 확인)
- [ ] 일부러 `validate` 를 실패시켜 보고, 에러 메시지를 보고 고쳐 보기

**Level 4 — 고급**
- [ ] **Draft PR** 로 풀이 중인 코드를 올리고 힌트 요청하기
- [ ] 두 사람이 같은 파일을 수정해서 **머지 충돌**을 만들고 해결해 보기 ([치트시트](06-git-cheatsheet.md#충돌-conflict-해결하기))
- [ ] `git log --oneline --graph` 로 머지 기록 살펴보기
- [ ] 저장소 개선 PR 올리기 (문서 오타, 새 태그 제안, 스크립트 개선 등)
- [ ] `.github/workflows/` 의 Actions 파일을 읽고 어떤 일이 자동화되어 있는지 설명해 보기
